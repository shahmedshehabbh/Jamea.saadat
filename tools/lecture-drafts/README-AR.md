# نموذج أولي لمسودات المحاضرات

هذه أداة محلية لمعالجة **محاضرة واحدة في كل تشغيل**. تأخذ ملف تفريغ نصي وبيانات وصفية، وتطلب من نموذج يعمل محلياً عبر Ollama إنشاء وصف وملخص تفصيلي ونقاط وكلمات مفتاحية. تحفظ النتيجة في ملف JSON منفصل بحالة `pending_review`.

**لا تتصل الأداة بـ Supabase، ولا تكتب في جدول `lectures`، ولا تنشر شيئاً.** لا تستخدم مفتاح Supabase أو Groq، ولا ترسل التفريغ إلى خدمة خارجية؛ الطلب يذهب إلى عنوان Ollama المحلي فقط.

## المتطلبات

- Python 3.10 أو أحدث.
- Ollama مثبت ويعمل على الجهاز.
- نموذج متعدد اللغات؛ مثال قابل للتجربة: `qwen2.5:7b`. يتطلب النموذج مساحة ذاكرة مناسبة، وجودة التلخيص تعتمد على الجهاز والنموذج.
- تفريغ نصي للمحاضرة أُخذ من مصدر تملك حق استخدامه. لا تحاول تنزيل صوت YouTube أو تجاوز قيوده بهذه الأداة.

## التشغيل على Windows

1. ثبّت Ollama، ثم افتح PowerShell من مجلد المستودع.
2. اسحب نموذجاً محلياً مرة واحدة:

   ```powershell
   ollama pull qwen2.5:7b
   ```

3. انسخ `metadata.example.json` إلى ملف محلي، مثل `lecture-13.json`، واملأ بيانات المصدر الفعلية. أبقِ روابط الوسائط الفعلية في `video_url` أو `audio_url` كي يُمنع تكرار المصدر. أنواع المواد المقبولة مطابقة للموقع: `الدرس` أو `مرئية` أو `صوتية` أو `نصية`.
4. احفظ التفريغ بترميز UTF-8 في ملف نصي. لا يلزم وضعه داخل المستودع.
5. نفّذ الأمر التالي بعد تعديل مسارات الملفات واسم النموذج عند الحاجة:

   ```powershell
   python .\tools\lecture-drafts\create_draft.py `
     --metadata C:\path\to\lecture-13.json `
     --transcript C:\path\to\lecture-13.txt `
     --model qwen2.5:7b
   ```

   إذا كان Ollama يعمل على عنوان محلي آخر، مرّره عبر `--ollama-url`. لا تستخدم عنواناً عاماً؛ التفريغ مخصص للمعالجة المحلية.

6. افتح ملف المسودة المنشأ تحت `tools\lecture-drafts\drafts\` وراجع كل حقل، خصوصاً أي اقتباس أو نسبة دينية وأي عنصر مسجل في `review.uncertainties`. المجلد مستثنى من Git كي لا تُرفع المسودات أو محتواها عرضاً.

## شكل المسودة والتوافق

يوجد محتوى قاعدة البيانات كاملاً تحت `fields`، بأسماء جدول الموقع الحالية:

`title`, `speaker`, `date`, `category`, `type`, `duration`, `image`, `description`, `summary`, `points`, `keywords`, `video_url`, `audio_url`

- `summary` نص Markdown يستخدمه الموقع لعرض الملخص المنسق.
- `points` مصفوفة نصوص JSON، و`keywords` نص عربي مفصول بـ `،`.
- لا يتضمن `fields` حقلاً `id`؛ يخصصه Supabase عند الإدخال.
- بيانات الحالة والمصدر والمراجعة خارج `fields`، فلا تُرسل إلى جدول الموقع عند مرحلة إدخال المسودة لاحقاً.
- قيمة `source_id` تُستنتج من معرّف YouTube أو من رابط المصدر، ويُرفض إنشاء مسودة أخرى للمصدر نفسه في مجلد المسودات.
- لا يُحفظ نص التفريغ داخل المسودة؛ يحفظ فقط بصمته SHA-256.

## المراجعة والحدود

يولّد النموذج اقتراحاً لا حكماً علمياً. لا يمكن ضمان خلو التلخيص الآلي من الأخطاء أو أن النموذج استوعب التفريغ الطويل كله؛ راجع المسودة مقابل التسجيل، وصححها قبل اعتمادها. لا تختلق بيانات مفقودة: اترك التاريخ أو المدة فارغين، وضع مواضع الغموض في قائمة المراجعة. إذا فشل النموذج أو أعاد JSON غير صالح، تتوقف الأداة برسالة خطأ ولا تحفظ مسودة ناجحة شكلياً.

## الاختبار

من جذر المستودع:

```powershell
python -m unittest discover -s .\tools\lecture-drafts -p "test_*.py" -v
```

الاختبارات محلية ولا تتطلب Ollama أو اتصالاً بالشبكة.

## المراحل التالية

بعد اعتماد هذا النموذج على تفريغ واحد، يمكن بناء واجهة مراجعة ومخزن مسودات منفصل في Supabase مع صلاحية المشرف فقط، ثم إجراء نقل صريح للمحتوى المعتمد إلى `lectures`. أما اكتشاف الفيديوهات والتفريغ فيحتاجان قراراً مستقلاً بشأن مصدر الصوت وحقوق استخدامه؛ لا يُنصح بأتمتة النشر.
